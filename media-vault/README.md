# MediaVault

Мобильная медиатека на React/Vite: манга, видео, книги, музыка и изображения в собственном Google Drive. Новый интерфейс использует Radix UI, Motion и Lucide. В библиотеке показываются реальные файлы из расшифрованного каталога.

**Сайт:** https://onikri.github.io/hots_tank.github.io/media-vault/

**Автоматический сервер импорта:** [Oracle Always Free — конфигурация и развёртывание](deploy/oracle/README.md). Сервер в аккаунте владельца ещё нужно развернуть и подключить; пустой `importServerUrl` не означает работающий backend.

## Первый запуск

1. Открой **Профиль → Войти через Google** и разреши чтение файлов Drive в окне Google. Отдельная кнопка подключения и ввод ID не требуются: приложение само ищет библиотеку после входа. Владелец — аккаунт `roma.shevchenko2020@gmail.com`. В коде хранится SHA-256 адреса для определения администратора. Папка другого аккаунта не используется: `storageFolderId` пустой, новая библиотека создаётся в Drive вошедшего владельца.
2. Если библиотека найдена, введи только её секретную фразу. Если библиотек пока нет, придумай и повтори фразу длиной от 12 символов → **Создать мою библиотеку**. Папка, зашифрованный каталог и ID создаются автоматически. Фразу нужно придумать самому: это не пароль Google, получить её в Google Cloud нельзя. Сохрани её, восстановления нет.
3. В **Библиотеке** можно добавлять локальные файлы или папку целиком. Формат определяется автоматически. Разделы «Аниме», «Манга», «Ранобэ», «Книги», «Музыка» отделены друг от друга. Укажи название тайтла/альбома и при необходимости сезон/том. При выборе папки дерево вроде `Ранобэ/Название/Том 1/...` разбирается автоматически. EPUB/PDF сам по себе не отличает ранобэ от обычной книги — раздел можно выбрать вручную.
4. Если найдено несколько библиотек, выбери нужную из списка. Проверка Drive не создаёт файлов; при ошибке доступа новая пустая библиотека не предлагается. Перед созданием приложение повторно проверяет наличие каталога, чтобы избежать случайных дубликатов. Для редкого ручного открытия достаточно вставить полную ссылку в «У меня есть ссылка на другую библиотеку».

Кнопка **Пригласить** выдаёт другу право чтения папки в Drive. Передай ссылку и секретную фразу отдельно. Для зрителя приложение запрашивает только чтение Drive.

Вход сразу запрашивает чтение Drive. При создании или первом изменении библиотеки Google может дополнительно попросить разрешить запись; это происходит из соответствующего действия автоматически. Зрителям доступ на запись не запрашивается.

Публичный Google OAuth Web Client ID уже указан в `config.js`. Веб-сайт не хранит пароль Google, Client Secret или ключи сервисного аккаунта. Для фоновой работы серверу нужен Client Secret только в его приватной конфигурации; в GitHub он не публикуется. Если Google отклоняет вход, в проекте OAuth должны быть включены Drive API, origin `https://onikri.github.io` и тестовые пользователи, включая владельца. Для локального запуска origin — `http://localhost:8080`. В origin нельзя добавлять путь проекта.

## Разделы и тайтлы

Одна библиотека — общий корень хранилища и одна секретная фраза. Это не общая папка со всеми сериями вперемешку. В режиме «Тайтлы» каждый тайтл показан отдельной карточкой; внутри находятся сезоны, тома и файлы. В режиме «Файлы» доступен общий список. Поиск работает по названию тайтла и файла.

```text
MediaVault
├── Аниме → Наруто → Сезон 1 / Сезон 2 → серии
├── Манга → Наруто → Том 1 / Том 2 → главы
├── Ранобэ → Название → тома
├── Книги → Название книги → файлы
└── Музыка → Альбом → треки
```

Одноимённые аниме, манга и ранобэ имеют разные папки. Сезоны одного аниме используют общую папку тайтла. Старые каталоги и ссылки на зашифрованные блоки читаются без перемещения или повторного шифрования существующих файлов; новые загрузки используют расширенную структуру `storage.version = 2`.

## Мировой каталог и автоматический импорт

Вкладка «Импорт» объединяет бесплатные каталоги **Kitsu, AniList, Shikimori,
MyAnimeList через Jikan, IMDb, TVmaze и Wikidata**. Ключи платных сервисов не
используются. Kitsu/AniList покрывают аниме и мангу; IMDb/Wikidata — кино,
TVmaze — сериалы. Ни один источник не содержит буквально все произведения мира.
Клиент объединяет записи по внешним ID и названиям, сохраняет синонимы на разных
языках и не подменяет недоступный источник демонстрационными карточками.

Поиск начинает запрос через 350 мс после ввода, отменяет устаревшие ответы,
показывает результаты каждого каталога по мере готовности и подсказки с
клавиатурной навигацией. Русский, английский, японский, китайский и корейский
передаются каталогам без потери символов; наличие перевода зависит от их баз.
Фильтры года передаются поддерживающим их сервисам; жанр/формат/возраст
применяются к полученным карточкам страницы. Фильтр озвучки сверяет первые
24 карточки страницы по публичному HTML источников на сервере, с кешем
15 минут и двумя одновременными проверками. Это проверка доступности, а не
полный индекс всех переводов; ошибки не считаются доказательством их отсутствия.

Карточка содержит реальные обложку, описание, жанры, теги, ограничения, даты и
число серий/глав, если источник их вернул. Неизвестные значения не выдумываются.
Японский эфир отображается в JST, публикации озвучки — отдельно и только когда
сам источник указал дату для эпизода/релиза. Выход в Японии не считается выходом
русской озвучки. Услуги метаданных могут ограничивать запросы или быть недоступны.

Схема импорта: **публичный источник → свой сервер → зашифрованный Drive**.
Видео не проходит через телефон, GitHub Pages или Cloudflare Worker. Drive не
скачивает произвольный URL сам — парсер и ffmpeg работают на VM. Интерактивного
запуска блокнотов в этом сценарии нет.

1. Один раз разверни сервер по [инструкции Oracle](deploy/oracle/README.md),
   настрой его HTTPS и Google offline OAuth, укажи публичный `importServerUrl`.
2. Войди владельцем, открой библиотеку и один раз разреши серверу фоновый Drive.
3. Найди тайтл, открой карточку, выбери найденную страницу, озвучку и сезон.
   Можно добавить всю опубликованную часть, одну серию, диапазон или список.
4. Нажми **Импортировать в коллекцию**. Задание остаётся на сервере после
   закрытия вкладки. Прогресс виден в «Загрузках»; коллекция обновляется сама.
   Отдельный режим «По ссылке» принимает публичные плееры, MP4/HLS и главы.

Сервер обрабатывает один файл за раз, проверяет результат, шифрует блоки по
4 МиБ и загружает их в Drive. Названия, описание, обложка и сведения о тайтле
попадают в зашифрованный каталог коллекции; сайт использует их после открытия.
Временное видео удаляется после файла. Токены Google используются только
адаптером Drive и не отправляются источникам. Шифрование на сервере требует
передачи ему производного ключа открытой библиотеки по HTTPS, без передачи фразы.

Очередь и Google refresh token зашифрованы на приватном диске VM; успешные и
отменённые задания удаляют свой ключ из записи, остальные истекают через 7 дней.
Перезапуск повторно ставит прерванное задание в очередь. Манифесты завершённых
файлов хранятся в Drive: повторный импорт их пропускает. После потери самой VM
можно развернуть сервер снова и отправить то же задание без повторной загрузки
сохранённых серий. Остановка пользователем происходит между файлами.

Бесплатные квоты и доступность VM проверяются в аккаунте; PAYG автоматически не
включается. Бюджеты Oracle уведомляют о расходах, но не запрещают списания.
Одна очередь сериализует серверные записи; пока она работает, не изменяй тот же
каталог с другого устройства. Drive v3 не гарантирует атомарный compare-and-swap.

## Парсер без API аниме-сайтов

Собственный `server/source_parser.py` извлекает ссылки и опубликованные эпизоды из HTML, `iframe`, атрибутов плееров и текстовой конфигурации. Для получения потоков из публичных плееров используются открытые наработки [anime-dl-core 0.5.1](https://github.com/ialakey/anime-dl-core), MIT: **Kodik, Aniboom, Sibnet и Animedia**. Это не поиск через API этих сайтов; ключ разработчика не требуется. API-адаптеры AniLibria, CVH и Alloha намеренно не зарегистрированы. REST/GraphQL-адреса блокируются клиентом источников.

Поддерживаются прямые HTTPS MP4, HLS VOD с TS/fMP4, диапазонами байтов и отдельной аудиодорожкой. Обычный AES-128 HLS с публичным ключом поддерживается; DRM, SAMPLE-AES, сессионные лицензии, платный доступ и закрытые аккаунты не обрабатываются. HLS сначала полностью локализуется на сервере; ffmpeg читает только локальные файлы и не получает сетевые URL.

Сайт может менять разметку, выдавать CAPTCHA, убирать видео, ограничивать регион или показывать плеер только после динамического запроса. Поэтому ссылка на YummyAnime/AnimeGo/Jut.su/AnimeVost/AniLibria не гарантирует извлечение. Если опубликованный список серий или поток отсутствует в доступном HTML, используй отдельные публичные ссылки серий/поддерживаемого плеера либо прямой MP4/HLS. Номера эпизодов не придумываются по заявленному количеству. Автоматический обход браузерных проверок не установлен. Исходный код устроен так, чтобы добавлять адаптеры конкретной разметки без смены хранилища и интерфейса.

## Шифрование и папки

- AES-256-GCM; PBKDF2-SHA256, 310 000 итераций; случайные salt и IV. Блок — 4 МиБ. ID файла и номер блока входят в authenticated additional data.
- Каталог содержит названия и сведения о коллекциях внутри шифрования. Дерево Drive: раздел («Аниме», «Манга», «Ранобэ», «Книги», «Музыка») → отдельная папка тайтла `collection-UUID` → при наличии сезон/том `part-UUID` → отдельный файл `asset-UUID` → `part-NNNNNN.enc`. Личные видео и изображения имеют дополнительные разделы «Видео»/«Фото». Названия тайтлов и сезонов/томов показаны на сайте после расшифровки, а в Drive для них используются непрозрачные ID. Серверный импорт также сохраняет `manifest.enc.json`.
- Локальные файлы шифрует браузер до отправки; серверный импорт шифрует VM до отправки в Drive. Фраза не отправляется серверу; производный ключ хранится в памяти браузера и в зашифрованной записи активного задания на своём сервере. Токены/ключи не публикуются в репозитории и не сохраняются в localStorage.
- Service Worker расшифровывает блоки для просмотра в памяти и поддерживает HTTP Range/перемотку. CacheStorage содержит только зашифрованные блоки, до 160 блоков. Сеансы разделены по вкладкам.
- При просмотре видео трафик Drive → устройство необходим. Рекомендуемый формат — MP4 H.264/AAC. Остальные кодеки зависят от браузера. Резервный режим скачивает файл целиком и требует соответствующего объёма RAM.
- Изображения, TXT, PDF, EPUB и CBZ/ZIP открываются в приложении. Книги и архивы скачиваются целиком. JSZip/EPUB.js загружаются с закреплённых версий CDN.

## Разработка и проверки

Node.js 22.12+, Python 3.10+, ffmpeg/ffprobe и Chromium:

```sh
cd media-vault
npm ci
python -m pip install -r server/requirements-service.txt httpx==0.28.1
npm run dev
```

Проверки перед публикацией:

```sh
npm test
npm run test:server
npm run test:notebook
npm run build
CHROMIUM_PATH=/usr/bin/chromium npm run test:ui
CHROMIUM_PATH=/usr/bin/chromium MEDIA_VAULT_SKIP_BUILD=1 npm run test:browser
```

Тесты используют настоящие AES-GCM/Web Crypto, ffmpeg, TS/fMP4-видео и подменённые HTTP/Google Drive. Проверяются совместимость Python ↔ браузер, диапазоны, шифрование, раскладка папок, восстановление, отсутствие видеозапросов из формы импорта, читатель без записи и размеры экрана 320/390/768/1280. Они не заменяют вход в реальный Google и проверку на физическом Android/iPhone. Отдельная проверка криптографии — `selftest.html`.

Старый Colab-блокнот оставлен для совместимости с прежними заданиями и не используется интерфейсом. После изменения его общих `server/*.py` или зависимостей выполни `python scripts/build-notebook.py`: блокнот содержит контрольные суммы источников, проверяемые до авторизации, и публикуется без результатов выполнения.

## GitHub Pages

Workflow `.github/workflows/pages.yml` сначала выполняет проверки, восстанавливает основной Tank guide из существующего архива и добавляет сборку MediaVault в отдельную папку. Остальные страницы сайта сохраняются. При legacy-источнике Pages workflow ждёт окончания автоматической сборки той же ревизии и затем публикует полный сайт. Рекомендуемый источник в Settings → Pages — GitHub Actions; сам workflow настройку источника не меняет.
