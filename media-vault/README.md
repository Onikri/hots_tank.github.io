# MediaVault — личная зашифрованная медиатека

Статическое приложение для видео, музыки, изображений, манги CBZ/ZIP и книг PDF/EPUB/TXT. Браузер шифрует файлы блоками по 4 МиБ; Google Drive хранит зашифрованные блоки и каталог. GitHub Pages публикует только приложение.

Адрес приложения: **https://onikri.github.io/hots_tank.github.io/media-vault/**

## Текущее состояние

MediaVault использует **React 19, Vite, Lucide React, Motion и Radix UI** для адаптивного интерфейса с плотным каталогом, фильтрами, сортировкой, просмотром медиа, мобильной навигацией и доступными диалогами. Палитра: тёмный шелковичный `#351E28`, оранжевый `#FF5C33`, небесный `#D8EFFF`, лаймовый `#E9F055`. Макет вдохновлён принципами мобильных медиакаталогов, но не использует чужие логотипы, исходный код или изображения.

GitHub Pages собирает React-приложение через Vite и включает его в существующий архивный сайт. Архив сайта и зашифрованные файлы в Google Drive не изменяются редизайном.

**OAuth Web Client ID уже внесён** в публичную конфигурацию `media-vault/config.js`. Для реального входа Google Cloud должен разрешать origin `https://onikri.github.io`, Drive API должен быть включён, а аккаунт владельца — добавлен в OAuth Test users. Автоматизированные тесты используют имитацию Google API и не подтверждают живой доступ к Google Drive на телефоне.

Ранее подготовленная папка Drive принадлежит другому аккаунту и отключена в конфигурации. При первом запуске приложение создаст новую папку в Drive выбранного владельца после его входа и задания секретной фразы. Администратор определяется хешем подтверждённого Google email в `config.js`.

## Однократная настройка Google

1. В [Google Cloud Console](https://console.cloud.google.com/) войдите в аккаунт будущего владельца. Создайте или выберите проект и включите **Google Drive API**.
2. В **Google Auth Platform** заполните Branding и Audience. Для личной группы выберите **External → Testing** и добавьте владельца и зрителей в Test users.
3. В Data Access добавьте `openid`, `email`, `profile`, `https://www.googleapis.com/auth/drive` и `https://www.googleapis.com/auth/drive.readonly`. Администратор запрашивает доступ Drive для записи и приглашений, зритель — чтение. Широкие Drive scopes требуют отдельной проверки Google для публичного распространения.
4. В **Clients → Create client → Web application** добавьте Authorized JavaScript origins: `https://onikri.github.io` и, при необходимости, `http://localhost:8080`. Путь `/hots_tank.github.io/media-vault/` в origin добавлять нельзя. Приложение использует popup token flow; Client Secret и redirect URI ему не нужны.
5. Впишите публичный Client ID, заканчивающийся на `.apps.googleusercontent.com`, в `media-vault/config.js`. Если владелец изменился, обновите `adminEmailSha256`: это SHA-256 email после `trim().toLowerCase()`. Сам email публиковать не требуется.
6. Сохраните изменения в `main`, дождитесь успешного workflow **Deploy Tank guide and MediaVault to GitHub Pages**. Рекомендуемый источник в **Settings → Pages → Source** — **GitHub Actions**, поскольку сайт собирается из архива и папки приложения. Если сохранена публикация из ветки (legacy), workflow сначала ждёт завершения legacy-сборки той же ревизии, затем публикует полный артефакт. Если завершение не подтверждено за 10 минут, публикация останавливается с инструкцией для повторного запуска. Workflow не меняет источник Pages и архив существующего сайта.

Никогда не добавляйте в репозиторий Client Secret, access token, пароль Google или секретную фразу библиотеки.

## Первый запуск

1. Откройте приложение → **Войти через Google** → выберите аккаунт владельца → **Подключить Drive**. Для двух шагов используйте один аккаунт.
2. Задайте свою секретную фразу минимум из 12 символов и повторите её. Нажмите **Создать новую библиотеку**. Фраза и ключ остаются в памяти устройства; восстановить забытую фразу невозможно.
3. Сохраните ссылку через **Скопировать ссылку-приглашение**: в ней указан ID зашифрованного каталога. ID также сохраняется в текущем браузере; на другом устройстве открывайте сохранённую ссылку.
4. Загрузите небольшой файл. После обновления страницы снова войдите, подключите Drive и откройте каталог с той же фразой.
5. Пригласите зрителя по email в интерфейсе: Drive выдаст папке право `reader`. Передайте ссылку и секретную фразу отдельно. В режиме Testing зритель также должен быть в Test users OAuth-приложения.

Когда доступ Google истечёт, нажмите **Подключить Drive заново**. Кнопка остаётся доступной в открытой библиотеке; повторно вводить фразу в этой вкладке не требуется. После перезагрузки страницы фраза потребуется снова.

## Шифрование и воспроизведение

- AES-256-GCM, PBKDF2-SHA256 с 310 000 итерациями; отдельные случайные IV для каталога и каждого блока. Идентификатор медиа и номер блока входят в authenticated additional data.
- Service Worker выдаёт полные потоковые ответы `200`, диапазоны `206` (включая `bytes=-N`) и `416` для невыполнимого диапазона. Перемотка не требует скачивания всего файла в память.
- Сеансы ключей и токенов разделены по вкладкам. После остановки Service Worker восстанавливает сеанс из памяти соответствующей открытой вкладки. При выходе сеанс вкладки очищается.
- CacheStorage содержит только зашифрованные блоки, максимум 160 блоков (около 640 МиБ). Браузер может очистить кеш; переполнение не должно прерывать сетевое воспроизведение.
- Видеоплеер рекомендует MP4 H.264/AAC. Поддержка других кодеков зависит от браузера. Есть кнопка загрузки файла целиком, если Service Worker недоступен; большие файлы могут исчерпать память телефона.
- Изображения, PDF, EPUB и CBZ скачиваются целиком. Крупные книги и архивы требуют соответствующего объёма памяти.

Права Google Drive ограничивают доступ к файлам. Проверка роли в интерфейсе лишь показывает доступные кнопки. Все, кому переданы и файлы, и фраза, могут расшифровать библиотеку. Шифрование не защищает от вредоносного обновления сайта или взломанного устройства. JSZip и EPUB.js загружаются с закреплённых версий CDN и выполняются с правами страницы.

Google Drive не гарантирует неограниченный трафик. Применяются квоты хранилища и API; автоматического перекодирования видео нет. Незавершённая загрузка может оставить папку `asset-...`, которую можно удалить вручную.

## Проверки

Локальная разработка интерфейса React (Node.js 22+):

```sh
cd media-vault
npm install
npm run dev
```

Откройте адрес Vite из терминала. Для локальной авторизации добавьте origin Vite (обычно `http://localhost:5173`) в Google OAuth Web Client, если это действительно нужно. Публичная версия работает с origin GitHub Pages.

Продакшен-сборка:

```sh
npm run build
```

Криптографию без Google можно проверить в `selftest.html`, размещённом вместе с опубликованным сайтом.

Регрессионные тесты Service Worker (Node.js 22+):

```sh
node --test media-vault/tests/range.test.cjs
```

Браузерные проверки: `media-vault/tests/browser.test.cjs` (Playwright, Chromium и установленный ffmpeg). Они проверяют интерфейс с подменёнными Google API, поэтому не подтверждают реальный OAuth и права Drive. Установка и запуск:

```sh
cd media-vault
npm ci
npx playwright install --with-deps chromium
npm test
npm run build
CHROMIUM_PATH="$(node -p 'require("playwright").chromium.executablePath()')" npm run test:ui
CHROMIUM_PATH="$(node -p 'require("playwright").chromium.executablePath()')" npm run test:browser
```

После настройки OAuth проверьте PNG, MP3, MP4, PDF, EPUB, TXT и CBZ; открытие после обновления; отказ при неверной фразе; зрителя без прав записи; перемотку видео и повторную авторизацию на Android и iPhone.
